# -----------------------------------------------------------------------------
# INTEGRAÇÃO DATABRICKS (OPCIONAL)
# Conecta ao Databricks SQL Warehouse para execução de checks de qualidade SQL
# diretamente em tabelas Delta / Unity Catalog.
#
# O servidor usa a Databricks SQL Statement Execution API, descobre automaticamente
# um SQL Warehouse e faz polling do statement. HTTP_PATH é opcional; quando
# informado, o ID após /warehouses/ é usado como preferência.
# Como obter os valores:
#   HOST       → Databricks Workspace → Settings → Developer → Connection details
#   HTTP_PATH  → opcional; SQL Warehouses → Connection details
#   TOKEN      → opcional; Settings → Developer → Access Tokens → Generate new token
#   CATALOG    → catálogo alvo no Unity Catalog (padrão: main)
# -----------------------------------------------------------------------------
# DATABRICKS_HOST=adb-123456789012345.6.azuredatabricks.net
# DATABRICKS_HTTP_PATH=/sql/1.0/warehouses/abc1234567890ef
# DATABRICKS_WAREHOUSE_ID=abc1234567890ef
# DATABRICKS_TOKEN=dapixxxxxxxxxxxxxxxxxxxxxxxxxxx
# DATABRICKS_CATALOG=main
#
# Alternativa segura ao PAT: o servidor tenta o segredo Databricks-AccessToken
# usando DefaultAzureCredential. Se a leitura falhar, tenta token Azure AD para
# Databricks e, por fim, `az account get-access-token` quando houver az login.
# A identidade gerenciada/service principal precisa ter permissão get no Key Vault.
# Nome atual usado pelo Lucid:
# AZURE_KEY_VAULT_URL=https://meu-keyvault.vault.azure.net
# Nome usado pelo projeto de referência (também aceito por compatibilidade):
# AZURE_KEYVAULT_URL=https://meu-keyvault.vault.azure.net
# AZURE_KEY_VAULT_SECRET_NAME=Databricks-AccessToken
